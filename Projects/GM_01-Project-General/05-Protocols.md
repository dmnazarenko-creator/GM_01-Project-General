# Описание протоколов обмена

> Статус: рабочий проект; неутверждённые технические решения отмечены отдельно.
> Регламент: [rules.txt](../../rules.txt); корпоративный стиль: [WAS.txt](../../WAS.txt), [WAS.pdf](../../WAS.pdf).
> Дата: 2026-11-12.

## 1. Modbus RTU

В каждом физическом сегменте индивидуальные адреса Slave: **1–247**, адрес **0** — широковещательный; диапазон **248–255** зарезервирован. Адрес верхнего концентратора и адрес Slave образуют составной адрес в системе, но не передаются двумя байтами в стандартном Modbus RTU без дополнительного прикладного механизма.

## 2. Конфигурация

Системная команда Modbus должна позволять сохранять адрес и скорость в энергонезависимой памяти. Код функции, регистровая карта, управление доступом и процедура применения значений — открытые вопросы.

## 3. Передача блоков прошивки

**128 байт = 64 регистра по 16 бит**. Один стандартный запрос функции **0x10 Write Multiple Registers** может нести до 123 регистров (246 байт данных), поэтому 64 регистра помещаются в один запрос. При включении управляющих регистров в ту же операцию необходимо учесть их количество и структуру.

Следует предусмотреть номер блока/смещение, длину, контроль целостности, подтверждение и повторы, а также криптографическую проверку подлинности всего образа перед активацией. [Modbus Application Protocol Specification V1.1b3](https://modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf).

## 4. Ethernet и групповая адресация

**Не утверждены**: стандартный Modbus TCP, Modbus TCP с расширениями или параллельный специальный протокол; двухэтапная адресная переадресация GM_05 принята как принцип; конкретный формат команд, ответы и Ethernet-протокол ещё определяются.

## 5. Двухэтапное управление рассылкой GM_05

**Шаг 1.** В адрес GM_05 передаётся управляющая команда для задания списка получателей: количество N и набор адресов Slave (пример: 5, 7, 12, 15) либо диапазон [10; 25]. Выбранные адреса должны находиться в диапазоне 1–247; дубликаты, пустой список и выход за пределы должны обрабатываться явно.

**Шаг 2.** Следующая команда, адресованная GM_05, используется как шаблон для последовательной отправки N стандартных Modbus RTU кадров внутри дочернего сегмента. Для каждого кадра изменяется адрес Slave и пересчитывается **CRC16/Modbus** по адресу, функции и данным. Базовый Modbus RTU на конечных устройствах не изменяется. Обработка ответов, задержек, ошибок и агрегированного отчёта — вопросы спецификации.

Следует определить конкретную функцию Modbus (предпочтительно стандартную запись регистров с семантикой GM_05 или частную функцию), формат хранения списка/диапазона и идентификатор команды. Нельзя трактовать второй кадр как свободный кадр к любому узлу: он должен быть недвусмысленно адресован GM_05 и защищён от ошибочного захвата.

## 6. Карта регистров обновления прошивки (черновой перечень)

| Поле | Назначение |
| --- | --- |
| Команда | BEGIN, WRITE_BLOCK, VERIFY, ACTIVATE, ABORT |
| Состояние | Готов / принимает / пишет / проверяет / ошибка |
| Идентификатор образа | Отделяет текущую сессию от предыдущих |
| Размер образа | Длина полезных данных в байтах |
| Тип устройства, версия | Проверка совместимости |
| Смещение блока | Смещение внутри файла (не абсолютный Flash-адрес) |
| Длина блока | Фактическое количество байтов, включая последнюю неполную порцию |
| Данные | **128 байт / 64 регистра** в основной транспортной порции; возможная внутренняя буферизация по 16 байт |
| CRC полного образа | Контроль случайных повреждений |
| Подпись / метаданные доверия | Проверка происхождения и целостности образа |
| Подтверждённое смещение | Объём, который действительно записан и проверен |
| Код ошибки | Диапазон, совместимость, Flash, CRC, подпись, очередь, повтор |

Функция 0x10 допускает до 123 регистров за запрос; для 64 регистров данных и служебных полей нужен ясный формат атомарной команды. Определить порядок упаковки байтов в 16-битные регистры, CRC16 кадра, отдельный CRC32 (если выбран) полного файла, покрываемые подписью поля, повторы запросов и различие между «принято в RAM» и «проверено во Flash». [Спецификация Modbus](https://www.modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf).

## 7. Системная конфигурация адреса и скорости

Системная команда должна позволять записать индивидуальный адрес 1–247 и скорость 9600, 19200, 38400, 115200, 230400 или 460800 бит/с в энергонезависимую память. После удержания кнопки более 15 с скорость восстанавливается к 9600 бит/с; рекомендуемый адрес восстановления — **1 (ещё не утверждён)**. Присвоение адреса 0 для индивидуальных запросов недопустимо: это broadcast без ответов. Формат команд, аутентификация, смена скорости без потери связи и предотвращение конфликта адресов остаются на проектирование.
